## F032 streaming markdown rendering behavior review (2026-11-07)

The reference implements `parseMarkdownIntoBlocks` and memoized `MarkdownBlock` components. It splits top-level markdown blocks while keeping blank lines within fenced code and display-math blocks, marks only the final block as streaming, and uses a streaming context so settled text avoids per-word rendering and Shiki does not repeatedly highlight changing code. Void-Agent now adapts that behavior in its existing ReactMarkdown renderer. Its GFM, LaTeX/KaTeX, Shiki, Mermaid, JSON, custom table/citation and link behavior remain wired; raw HTML remains disabled and ReactMarkdown's default URL protocol filter is retained. The splitter preserves loose-list separators while collapsing long blank runs to one retained separator. `src/components/markdown.test.tsx` mounts the component and verifies settled blocks do not rerender while the tail changes; parser tests include a 50,000-line blank-run case. Focused tests pass; integrated typecheck/build are pending, so F032 remains PARTIAL.
